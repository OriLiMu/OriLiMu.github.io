# Cursor IDE的实际使用体验是怎样？

章 从去年开始，订阅了10个多月了，断断续续用 Cursor 辅助开发了大概有5、6个产品，两个开源项目，感觉可以谈谈体会：对编程行业肯定是有影响，但并不觉得会取代程序员，可能会减少对初级程序员的需求。

优势满足了我去年对AI IDE的大部分想象：解决了我去年用ChatGPT生成代码时遇到的绝大部分问题：最近ChatGPT帮我开发了一个小项目总是能使用最新的模型：Claude3发布后第二天就用上opus 200K；

gpt4o发布后也是第二天用上；

前不久 Claude3.5 发布后也是第二天用上，现在已经完全使用Claude3.5来辅助编程，Claude 3.5 Sonnet 给 AI IDE 带带来了质的变化，速度快，代码一次运行成功率很高，生成的代码大多没有报错。

如果用自己的API KEY，也可以免费用。

与IDE融合最好的AI：这是去年 11 月刚用的时候它就有的优势，选中任何代码 CMD+L就可以用AI进行修改对话，CMD+K可以针对性的修改代码，还有其他很多快捷功能。

自动将工程目录作为对话的上下文：经常用AI 生成代码的应该知道这个的作用。

可以自动爬取并嵌入网络上的任意网页用作RAG：通常会将开发文档放进去，通过@ 来实现Chat With 官方文档。

一键 AI Fix Bug：IDE里报错，terminal 里报错后，一键AI Fix Bug，去年就有的功能，成功率比较高长文本对话：使用200K模型后，可以将整个工程代码放进对话中，实现比如优化整个仓库代码的需求一键导入 vscode 的插件和配置：cursor 是 fork 了 vscode 的 AI 原生 IDE ，所以可以一键导入 vscode 的插件和配置，用户的切换成本很低。

IDE相比插件长期优势更大：理论上 AI IDE 有更多自定义能力，也能占据程序员工作的最大入口，长期看会拉大和插件的差距。

未来如果要内置类似 devv 这样的程序员AI搜索、Devin这类的Agent是比较容易的。

可以创建文件：前不久新发布的Composer，可以选中多个文件让AI同时修改，甚至能自动创建新文件。

Agent的雏形快出来了。

不足代码出错的情况还是有，需要花时间debug，比如最近总是在中文字符串里面不能正确转义双引号。

可能是模型的问题。

Composer可能刚发布还不够完善，添加的文件不能太多，也容易编辑失败，交互也有点复杂。

无法取代架构师的作用。

能做规划，但易出错还是不敢用，应该还是模型的问题。

毕竟是个IDE，目标用户是程序员，非程序员想借助它实现产品有难度。rag需要增强，有时感觉不精准。

影响极大增强经验丰富的程序员的效率：因为靠提示词驱动，得大致清楚怎么设计你的应用，虽然 Claude 3.5 已经可以比较好的做一些简单的规划类问题，但容易出错。

如果你自己也不知道对错，bug 有时可能解决不了，只能做做玩具。

降低了编程学习难度：有一些没用过的框架、库、甚至语言，只要你了解编程的思维，也可以写出可运行的项目。

可能会对面向程序员的其他产品产生影响：比如Devv.ai，之前经常用，现在因为可以 rag 官方文档，回忆了一下好像一两个月没有打开过，而且 Cursor 里面其实带了一个不是很好用搜索引擎。

解决Bug现在也是点一下先用AI解决，几乎不用去 google 里面搜索。这个入口太强，会拦截大部分交互动作。

国内可以追赶：Cursor 的创新更多是在交互层面，一个更“高级的套壳”，模型用的其他家，国内如果要模仿也可以，完全追赶得上，甚至超越。

我的前东家也一直在准备采购，企业客户的购买意愿应该是有。

测试应该要更重要：有很多代码生成以后，可能不会去严格的Review，一个个黑盒构成的应用，总感觉不是很踏实。

如果能出现AI驱动的自动化测试，代码审查工具，应该会比较需要。
